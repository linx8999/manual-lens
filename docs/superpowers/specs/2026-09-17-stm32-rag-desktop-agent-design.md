# STM32 手册桌面智能体设计规格

## 1. 目标

构建一个 Windows 桌面应用，使用户可以对本机 STM32 手册提问。应用先检索本地知识库，再调用用户配置的 OpenAI 兼容 API 生成回答。回答必须带有页级引用；右侧阅读器自动打开对应文档页面，并显示该文档目录。

应用不依赖外部浏览器。用户双击桌面快捷方式即可启动。知识库原始文件、索引、配置、缓存、日志和会话全部保存在 `D:\STM32RAG智能体\data`，除非用户主动修改数据目录。

## 2. 范围

### 2.1 必须实现

- Windows 桌面应用与桌面快捷方式。
- PDF、XLSX、PNG 和 JPG 文件导入。
- 原始文件 SHA-256 去重与 D 盘本地存储。
- PDF 逐页文本、基础版式和目录提取。
- Excel 工作表与单元格内容提取。
- 图片作为可浏览资料导入。
- 页级文本块、章节信息、实体和文本位置保存。
- SQLite 持久化。
- 关键词检索、向量检索、别名扩展和结果融合。
- OpenAI 兼容聊天接口和向量接口，地址、密钥和模型可独立配置。
- 带页级引用的流式回答。
- 三栏桌面界面：会话与资料库、聊天、阅读器。
- PDF.js 原件阅读、目录跳转、页码跳转、缩放和引用定位。
- Excel 表格阅读和行定位。
- 图片查看。
- 索引进度、失败重试、删除资料和重建向量。
- API 密钥使用 Windows 加密能力保护。
- 无 API 配置时仍可浏览、搜索和检索资料。
- Windows 安装包、桌面快捷方式和可重复的测试流程。

### 2.2 明确不实现

- 公有云部署、远程账号和多用户权限。
- 手机端或局域网浏览器访问。
- 知识图谱、自动写代码执行和无人监督的多智能体流程。
- 自动修改或重新发布原始手册。
- 在用户未配置 API 时伪造模型回答。

## 3. 技术路线

### 3.1 应用框架

- Electron 作为桌面运行时。
- Electron 内嵌 Chromium 只用于渲染桌面界面，不打开系统浏览器。
- React、TypeScript、Vite 和 Electron Vite 构建界面。
- Electron 主进程承载文件系统、数据库、检索、API 调用和导入任务。
- Preload 使用白名单 IPC API，Renderer 不直接访问 Node.js 或任意文件路径。

### 3.2 数据与检索

- Node.js 24 内置 SQLite (`node:sqlite`) 作为单机嵌入式数据库，直接使用 Electron 自带运行时，避免第三方原生模块 ABI 问题。
- 页级全文索引采用 SQLite FTS5；中文查询由应用层生成字符和二元词组查询。
- 向量以 Float32Array BLOB 保存。
- 向量规模按约 1 万文本块设计，查询时在内存中执行精确余弦相似度计算。
- 关键词、向量和结构信号使用 Reciprocal Rank Fusion 融合。
- 不部署 ChromaDB、Milvus、Qdrant 等外部服务。

### 3.3 PDF 与阅读器

- 主进程使用 PDF.js 提取页数、文本、文本坐标和书签。
- Renderer 使用 PDF.js Canvas 和 Text Layer 渲染原件。
- 文档二进制通过受控 IPC 提供，不启用 Renderer 的文件系统权限。
- 引用定位优先使用 PDF 物理页；同时显示 PDF 页码和手册印刷页码。

## 4. 本地目录

默认数据根目录为：

```text
D:\STM32RAG智能体\data
```

目录结构：

```text
data\
  library\       原始 PDF、Excel 和图片
  index\         knowledge.db 等索引文件
  cache\         页面渲染和缩略图缓存
  logs\          导入、检索和 API 调用日志
  backups\       知识库备份
  settings.json  非敏感设置
  secret.bin     经 Windows 加密后的 API 密钥
```

若 D 盘不可用，首次启动时要求用户选择有效目录。应用不会静默把知识库保存到 C 盘。

## 5. 知识库模型

### 5.1 documents

| 字段 | 含义 |
|---|---|
| id | 稳定 UUID |
| sha256 | 文件内容哈希，用于去重 |
| title | 手册标题 |
| original_filename | 导入时文件名 |
| stored_path | D 盘中的相对路径 |
| kind | `pdf`、`xlsx`、`image` |
| page_count | 逻辑页数 |
| status | `pending`、`indexing`、`ready`、`error` |
| metadata_json | 版本、型号、文件类型等 |
| created_at / updated_at | 时间戳 |

### 5.2 pages

每一页保存文档编号、物理页码、印刷页码、文本、尺寸和文本坐标。Excel 的每个工作表作为一页，原始行号作为位置记录。

### 5.3 toc_nodes

保存标题、层级、父子关系和目标页。没有内嵌书签的 PDF 从识别出的编号标题生成目录节点。

### 5.4 chunks

文本块保存文档、页码、块序号、章节、原文、检索字符、实体 JSON 和位置 JSON。默认长度约 700 个中文字符，重叠约 120 个字符；文本块不得跨页。

### 5.5 embeddings

保存文本块编号、模型、维度和 Float32 向量。不同维度的向量不能混用。更换向量模型后，旧向量保持可用，直到新模型重建完成。

### 5.6 conversations 与 messages

保存会话标题、消息角色、正文、状态、引用和创建时间。引用至少保存文档编号、页码、文本块编号和摘录。

## 6. 导入流程

1. 用户选择文件，或应用扫描资料库目录。
2. 计算 SHA-256；已存在相同哈希时标记为重复，不重复保存和向量化。
3. 将原文件复制到 `data\library`。
4. 建立文档记录和导入任务。
5. 提取页、目录、文本和位置。
6. 生成页级文本块和实体。
7. 写入 SQLite。
8. 如果配置了向量模型，则批量请求 embedding。
9. 写入向量并执行一次检索自检。
10. 将文档状态改为 `ready`。

导入任务可中断和恢复。相同文件不重复向量化。不同文档使用相同向量模型时可以复用已有向量，不重新请求相同文本块。

## 7. 检索流程

### 7.1 问题分析

规则分析器提取：

- STM32 型号，例如 `STM32F103C8T6`。
- 外设，例如 `GPIO`、`USART`、`SPI`、`I2C`、`ADC`、`TIM`、`RCC`、`NVIC`、`EXTI`。
- 标识符，例如 `GPIOA`、`PA9`、`USART1_TX`、`AFIO_MAPR`。
- 问题类型，例如配置、寄存器、电气参数、引脚、错误排查。

### 7.2 召回

- FTS5 返回关键词候选，默认 60 条。
- 向量检索返回语义候选，默认 60 条。
- 别名扩展把中文名称映射到英文缩写。
- 型号、外设和寄存器精确命中获得加权。

### 7.3 融合与选择

使用 RRF 融合排名，并应用文档类型、章节标题、页码邻近和精确标识符加权。最终选择 8 到 12 个互不重复的证据块。若证据不足，回答阶段必须明确说明。

## 8. 回答生成

聊天提示词要求模型：

- 仅依据提供的证据回答。
- 保留寄存器、地址、位、复位值和电气参数原值。
- 每个关键结论引用至少一个 `[S#]`。
- 区分手册原文和推理。
- 无充分证据时拒绝猜测。

回答 UI 将 `[S#]` 映射为可点击来源。第一个核心来源自动打开右侧阅读器。

没有配置聊天 API 时，应用显示检索结果、来源和明确提示，不生成伪答案。

## 9. API 配置

分别配置：

- 聊天 `Base URL`
- 聊天模型
- 聊天 API Key
- 向量 `Base URL`
- 向量模型
- 向量 API Key

兼容 OpenAI 的 `/chat/completions` 和 `/embeddings` 路径。两个 API Key 可以相同。应用提供连接测试、超时和明确的 HTTP 错误提示。

密钥使用 Electron `safeStorage` 调用 Windows DPAPI 加密后写入 `secret.bin`。密钥不得出现在日志、SQLite 明文设置或错误消息中。

## 10. 桌面界面

### 10.1 三栏工作台

- 左栏：新对话、历史会话、文档列表、资料库管理入口。
- 中栏：消息、流式回答、引用卡片、提问框。
- 右栏：阅读器目录、原始页面、页码、缩放、搜索和高亮。

左右栏支持折叠。窗口宽度不足时，阅读器切换为覆盖式面板，不压缩到不可使用。

### 10.2 首次启动

1. 确认或选择数据目录。
2. 配置 API。
3. 测试聊天与向量接口。
4. 导入内置样例资料。
5. 显示逐步进度。
6. 完成后进入问答工作台。

用户可跳过 API，直接浏览资料并在稍后配置。

### 10.3 资料库管理

支持导入文件、查看页数和状态、重试失败文件、删除文档及索引、查看重复文件、重建向量和备份知识库。

## 11. 阅读器

- PDF 目录可折叠、展开和跳页。
- 支持上一页、下一页、页码输入、缩放、适合宽度和旋转。
- 点击聊天引用后，在同一窗口打开正确文档和页面。
- 每本文档记住最后查看页面。
- 在文本层中高亮命中摘录；无法可靠匹配坐标时，仅定位页面并在来源卡显示摘录。
- Excel 使用表格视图并高亮引用行。
- 图片使用缩放查看器。

## 12. 错误处理

| 情况 | 行为 |
|---|---|
| PDF 损坏 | 保留原文件，记录失败页和错误，允许重试 |
| PDF 为扫描件且无文本 | 标记“需要 OCR”，不伪造页文本 |
| API Key 错误 | 停止当前请求，提示设置页，不记录密钥 |
| API 超时 | 允许重试，检索结果仍可浏览 |
| 向量维度变化 | 要求重建向量，不用不兼容向量检索 |
| 数据库写入失败 | 原子替换索引文件，保留上一份可用备份 |
| 应用异常退出 | 导入任务保留检查点，下次启动可继续 |
| D 盘不可用 | 阻止初始化并请求新的数据目录 |

## 13. 安全

- Renderer 启用 `contextIsolation`，关闭 `nodeIntegration`。
- IPC 只允许预定义的文档、检索、设置和会话操作。
- 文档读取以内部文档编号寻址，不接收任意绝对路径。
- 外部链接只能在用户确认后由系统浏览器打开。
- API 请求只发送检索出的少量原文，不自动上传整本手册。
- 日志对请求头、密钥和可能的敏感上下文进行过滤。

## 14. 测试与验收

### 14.1 自动测试

- 单元测试：分页、分块、哈希去重、查询分析、RRF、向量维度校验、目录映射、密钥脱敏。
- 集成测试：导入真实 PDF、建立数据库、关键词检索、引用生成、会话持久化。
- 无网络测试：使用假 API 响应验证聊天流式解析和 embedding 批处理。
- Renderer 测试：聊天、设置、资料库和引用跳转事件。
- Electron 端到端测试：启动、导入、提问、打开引用页、重启后恢复状态。

### 14.2 当前样例验收

- 6 个 PDF 文档可导入。
- 两份完全相同的 `STM32F103x8B数据手册（中文）.pdf` 只建立一份文档记录。
- PDF 总页数约为 1685 页。
- 每份 PDF 的目录可显示并跳页。
- Excel 显示 50 行、8 列，并可定位引脚行。
- 问题“PA9 怎么配置成 USART1_TX”能召回参考手册、数据手册和固件库中的相关证据。
- 配置有效 API 后，回答包含引用；点击引用打开正确页面。
- 未配置 API 时，应用仍能展示检索证据和原件页面。
- 关闭并重新打开应用后，资料、会话和阅读位置仍存在。

### 14.3 安装验收

- `pnpm build` 成功。
- `pnpm test` 成功。
- `pnpm test:e2e` 成功。
- `pnpm dist:win` 生成 NSIS 安装包。
- 安装后桌面出现快捷方式。
- 双击快捷方式可在不打开外部浏览器的情况下进入工作台。
- 新产生的知识库文件位于配置的 D 盘目录。

## 15. 交付结构

```text
stm32RAG智能体\
  src\
    main\        Electron 主进程、数据库、导入、检索和 API
    preload\     安全 IPC 桥
    renderer\    React 桌面界面
    shared\      主进程与界面共享类型
  tests\
    unit\
    integration\
    e2e\
  resources\     应用图标和首次启动资料清单
  docs\          设计和技术说明
  release\       安装包输出
```

## 16. 完成定义

只有同时满足以下条件才视为完成：

- 规格中的全部必须实现项均有代码和测试覆盖。
- 样例手册已实际导入 D 盘知识库。
- 自动测试、构建和 Windows 打包命令均以退出码 0 完成。
- 使用真实安装包验证快捷方式启动和核心闭环。
- 在没有有效 API 密钥的环境下，阅读、检索和错误提示仍可工作。
- 在配置兼容 API 的环境下，回答、引用和自动翻页闭环可工作。
